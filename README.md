# 工单运营 · 发生量估计

历史完整批次里有 **发生日** 和 **上报日**；最近几天只有已经报上来的部分。这个页面先从已成熟
的批次估计每个渠道的上报延迟分布，再把截止日之前实际看得到的数量送进 **非负反推模型**，
估计最近各日总共发生了多少、还有多少没报上来。

## 运行

```bash
.venv/bin/python -m ticket_ops.server --data data/tickets.csv      # 打开 http://127.0.0.1:8000
```

依赖只有 Python 标准库 + numpy + scipy。演示数据已生成在 `data/tickets.csv`；需要重建时：

```bash
.venv/bin/python tools/generate_data.py --out data/tickets.csv
```

## 页面上的三条曲线

- **原始上报曲线**（蓝）：截止日之前每天实际收到的上报量。
- **估计发生曲线**（橙，带 90% 区间）：反推出来的当日发生量，含尚未上报的部分。
- **回推上报曲线**（绿虚线）：把估计发生量按延迟分布折回报日。它应当与原始上报曲线贴合；
  两条都只画到截止日，便于直接检验拟合是否成立。

点选图中任意一天，右侧「单日拆解」会显示这一天的估计量如何按时滞拆分：哪些是已上报、
哪些是模型补上的未上报部分，以及每一段延迟各贡献多少。

## 方法要点

1. **按渠道单独拟合，最后才相加。** 每个渠道各自训练延迟分布、各自反推，汇总时只加数量，
   不先把渠道混成一个平均延迟（`tools/generate_data.py` 里各渠道延迟形状差异很大，
   混合会直接引入偏差）。
2. **成熟历史才进训练。** 只有截止日往前至少一个完整时滞窗口（`KMAX`，默认 30 天）的发生日
   才参与延迟训练。未成熟批次永不回流——否则「最近变慢」会被错当成「延迟分布变长」。
3. **非负反推，不截零。** 约束写成 `已观察数量 + 未知未上报 ≥ 0`，解由非负最小二乘
   （`scipy.optimize.nnls`）直接给出。没有「先解线性模型再把负数截成 0、然后当作原模型的解」
   这一步；如果目标被污染成负数，NNLS 会老老实实返回边界解并留下很大的残差。
4. **平滑可调。** 平滑权重作用在发生曲线的 **一阶差分** 上（二阶差分会把曲线合法的周内
   水平变化也罚掉，导致系统性高估）。调大平滑后数据项残差会如实变大，页面上不隐藏。
   默认值 0.05 由回放校准选出：在 0 / 0.05 / 0.3 / 5 的对比中，这一档的 90% 区间实际
   覆盖率最接近名义水平。
5. **不确定范围。** 来自对成熟训练日与观察计数的自举重采样（`DEFAULT_DRAWS`），再叠加
   平滑参数相邻取值（0.5×、1×、2×）的敏感性包络，取更宽者。
6. **三种稳定性情形都会报警：**
   - **渠道突然变慢**：用截断校正后的条件分布与训练期比较（只看尚未成熟的日子的可见部分，
     不需要知道缺失的尾部，也不会把未成熟数据喂回训练）。TV 距离或当日上报占比越界即报警。
   - **某天完全停报**：按同星期历史中位数判断上报日是否异常低迷；受影响的发生日降级为
     **下界**，并放宽上界，而不是让缺失量把估计压小。
   - **历史从未覆盖的延迟**：出现比训练时滞更长的延迟时，对应发生日按已观察量计为下界，
     并提示更长延迟无法被分解。
7. **回放检验。** 用更早的截止日重跑整条链路——每次回放都会把该截止日之后的报送 **物理排除**，
   所以只能用到当时已成熟的历史。评分只针对「当时尚未报齐、如今已成熟」的发生日，并与
   「直接用当时已上报」的朴素基线对比。比较基准是这些日子到当前截止日为止的累计上报量，
   因此永久丢失的报送会计为模型误差。

## 目录

```
ticket_ops/data.py        CSV 读取与校验（截止日之前的上报才可见）
ticket_ops/model.py       延迟训练、非负反推、报警、回放、汇总
ticket_ops/server.py      标准库 HTTP JSON API + 静态页面
ticket_ops/static/        页面（Chart.js 4 本地打包）
tools/generate_data.py    确定性演示数据，内含变慢/停报/超长延迟三种情形
tools/evaluate.py         用更晚的成熟快照做离线校准
tests/                    unittest：模型约束 + HTTP 契约（22 项）
```

## 测试

```bash
.venv/bin/python -m unittest discover -s tests
```

覆盖的关键不变量包括：未成熟日不进入延迟训练、新鲜积压不能弯折延迟分布、估计值永不低于
已观察量、被污染成负数的目标不会被「截零后冒充求解」、渠道分开拟合、三类报警都能在演示数据上
触发、回放只使用当时可用的历史、汇总等于各渠道之和。
